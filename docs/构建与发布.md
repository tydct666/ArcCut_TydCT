# 构建与发布

版本以 package.json 为准，`node scripts/version.cjs` 检查 Cargo、Tauri、标题；修改版本后运行 `node scripts/version.cjs --write`，重新生成 Cargo.lock 并构建。关于页由 Vite 注入同一版本。发布标签必须为 `v<版本>`。

归档递归验收使用 Python 3.11+ 标准库（不属于运行包依赖）。可通过 `ARKCUT_TEST_PYTHON` 指定解释器。

工具版本：Windows x64 / VS C++ Build Tools 与 Windows SDK，Node 24.19.0、pnpm 11.25.0、Rust MSVC 1.99.1。依赖通过 pnpm-lock.yaml、Cargo.lock 锁定。`scripts/env.ps1` 可使用工程内 tools 工具链，也支持正常 PATH，不依赖某台电脑的个人目录。

```powershell
pnpm install --frozen-lockfile
pnpm build
cargo test --locked --manifest-path src-tauri/Cargo.toml --lib
cargo test --locked --manifest-path src-tauri/Cargo.toml --test update --features update-test-hooks
./scripts/prepare-github.ps1
./scripts/package.ps1 -Portable
node scripts/verify-release.cjs dist/ArkCut-0.17.1-win64-light dist/ArkCut-0.17.1-win64-light.zip
```

运行组件的来源、版本与校验策略锁定在 `release/runtime-lock.json`。应用从 Gyan Windows 构建站点取得 FFmpeg 9.0.2，验证归档长度、SHA-256 以及两份可执行文件哈希；界面使用系统 Evergreen WebView2（最低主版本 155），缺少时从微软取得官方安装器并验证 Authenticode 签名。原生准备窗口不依赖 WebView2。运行包无需 Node、Rust、Python。生产编译不得启用任何 `*-test-hooks` 特性。开发者需要本机媒体回归时可单独运行 `bootstrap-runtime.ps1`，它只准备开发测试用 FFmpeg，不参与打包。

可选媒体集成测试需先运行 `scripts/bootstrap-runtime.ps1` 和 `python tests/fixtures/generate.py`，再运行 `cargo test --locked --manifest-path src-tauri/Cargo.toml --test jobs -- --ignored`。本地更新验收另需 Python 的 `cryptography` 包，依次运行 `tests/update-build-pair.ps1` 和 `node tests/update-e2e.cjs`；随后可运行 `tests/update-gates.cjs`、`tests/update-package-smoke.cjs`。A/B 二进制由构建脚本固定输出到 `tests/results/revision17-light-final/binaries`，E2E 从该处读取；`ARKCUT_UPDATE_E2E_OUT` 只指定 E2E、后续检查及资源监控的运行结果目录，默认 `tests/results/revision17-light-final`。运行结果目录可单独更换，二进制需先由本次源码重新构建。`revision12_audit` 为显式素材验收，需同时设置 `ARKCUT_R12_AUDIT_PROJECT` 与 `ARKCUT_R12_AUDIT_OUTPUT`；这些可选检查不会隐式读取内部工程或用户素材。

真实素材暂停回归入口为 `tests/pause-transition-regression.py`、`tests/pause-transition-output-check.py` 与 `tests/frequent-pause-regression.py`，通过各脚本的 `--help` 查看输入参数。源码只提供检查逻辑，不附带私人录屏、项目或视觉标注。前两项分别比较暂停边界与独立标注、对实际导出做逐帧像素和时序检查；替换数据集时显式传入基线项目、标注及独立输出目录。默认路径均相对仓库根目录，已有项目和成片不被覆盖。每次更换 CLI 或标注后使用新结果目录，避免混用旧证据。

低余量导入回归使用显式测试构建：设置 `ARKCUT_LOW_HEADROOM_VIDEO` 为验收录屏的绝对路径，`ARKCUT_LOW_HEADROOM_OUT` 为尚不存在的结果目录，再运行 `cargo test --locked --manifest-path src-tauri/Cargo.toml --features resource-test-hooks --test low_headroom_import -- --ignored --nocapture --test-threads=1`。它把可用内存计数器上限设为 2 GiB、总内存上限设为 16 GiB，验证持续软压力下完整导入及临界物理内存、提交空间保护；不会占满真实内存，也不能代替真实低内存硬件验收。交付程序不启用该测试特性。

`scripts/package-source.ps1` 只复制 `release/source-files.json` 白名单，其中 `distributionMaterials` 精确纳入 `release/distribution-files.json` 的 19 项已审核材料，不遍历整个本地材料目录。`scripts/prepare-github.ps1` 生成独立待上传目录及文件、体积、源码摘要审计，不初始化、不推送、不发布。源码扫描拒绝个人路径、常见令牌及私钥文件；提交前仍需人工检查白名单。内部需求、修改单、历史验收日志、录屏、音乐、缓存、机器工具链和密钥留在本地。轻量包也只放公开文档。

`sourceSnapshot` 是白名单文件名与内容的 SHA-256；无 Git 的本地候选通过此摘要追溯。正式工作流还记录标签指向的提交和构建编号。源码 ZIP 与轻量 ZIP 的 SHA-256 写入 `SHA256SUMS.txt`，便携 manifest 记录每个拥有的文件。冻结源码后先运行 `./scripts/prepare-github.ps1`，再统一编译、打包与签名；`verify-release.cjs` 强制比较当前白名单、待上传目录、独立源码 ZIP、包内源码与 manifest 的摘要。签名验证通过受签名保护的 manifest 哈希绑定同一源码快照；任何收尾改动都需要重新生成整组候选。

当前交付版本为 0.17.1。版本化运行目录和源码 ZIP 与稳定名称的 `dist/ArcCut_TydCT`、更新索引、签名、校验和组成同一批交付；最终核对实际 EXE、两种运行包内源码、ZIP 内容和 manifest，不以文件名或修改时间代替内容验证。`package.ps1` 默认只生成源码，当前便携构建使用 `-Portable`；`package-light.ps1` 是旧开发版离线包的转换脚本，不用于当前在线准备版。完整离线包由 `package-offline.py` 从已验证轻量目录生成，生成后补齐离线 ZIP 的 SHA-256。只有更新索引和签名全部重新验证后，旧交付才可移入历史归档；已有项目、素材及运行中的外部副本保持原位置。

## GitHub 配置

本地完整离线包可在轻量包校验后，用 `python scripts/package-offline.py --runtime <固定WebView2目录> --media <媒体EXE目录> --media-notices <FFmpeg许可和README目录>` 生成。核心界面运行时哈希锁定在 `release/offline-runtime.json`，媒体哈希仍使用 `runtime-lock.json`；启动只接受校验通过的包内组件。该额外本地包不替代轻量更新资产，也不自动授予旧离线组件的公开分发验收状态。源码、应用与更新器均来自同一次同步构建。

发布编译由 `scripts/release-build-env.ps1` 设置路径映射和仅文件名的 PDB 引用；包含 Cargo 依赖的编译路径也会规范化。打包要求新的空暂存目录，避免混入旧文件。`scripts/audit-public.cjs` 以有界缓冲扫描文本及二进制，阻止本机路径、配置报告、密钥文件和常见凭据进入公开交付，校验阶段再次运行。扫描不代替完整安全审查。

`scripts/prepare-github.ps1` 校验后统一更新 `dist/ArcCut_TydCT`，保留名称稳定的最新快照；发布目录和 ZIP 更新后重新生成哈希与签名。若目标已包含 `.git` 目录或 worktree 文件，脚本会在创建暂存文件前停止，完整保留现有仓库。此时先用 `node scripts/source-list.cjs <全新目录>` 导出，再在既有仓库中审阅并同步文件，保留 Git 历史；`--help` 只显示用法。诊断、私钥和本机环境资料保留在工作目录，均不进入白名单。普通开发编译不强制使用发布映射。

发布扫描同时检查截图／录屏来源文件名、模板来源元数据、已废弃模板和旧诊断版本。当前模板只保留检测所需参数。Rust 许可按锁定的 Windows 依赖图收集，构建依赖保守保留，本机其他缓存版本不进入包。所有本机打包审计默认写入 `outputs/release-audit/<版本>`，dist 只保留交付文件。

第三方补充材料由 `release/distribution-files.json` 锁定文件、长度、哈希和来源。必要的许可证、来源记录与精确 MPL 源码归档随公开源码的 `distribution-support` 一起提交；干净检出无需从内部工作目录补文件。约 250 KB 的材料不含运行时或旧离线归档，`.gitignore` 仅为这 19 项解除忽略。本机候选打包会逐项核验这些材料；正式打包使用 `-FinalRelease`，还要求完整审计通过且不存在待办项。发布工作流在构建前核验已提交材料，保留人工审批和完整性门禁，单独修改 CI 的审批变量不能跳过文件检查。

安装锁定依赖后，`node scripts/generate-distribution-docs.cjs --check` 从实际 Windows Cargo 图和前端生产依赖重新生成并比对 Rust、NPM、MPL 源码三份清单；打包与 CI 自动执行。依赖更新时先运行该脚本的 `--write`，审核变化、补齐精确 MPL 源码及许可，再更新 `release/distribution-files.json` 对应长度和哈希、版本及审核状态。脚本不会自动授予分发批准；来源说明与 README 属于维护者审核的文档。

轻量分发清单只覆盖实际随附的应用依赖许可及 MPL 对应源码，不携带 FFmpeg、固定 WebView2 或其归档。FFmpeg 由用户机器直接从提供者下载，其 LICENSE/README 与组件同存；旧离线分发的静态依赖与构建记录缺口仍保留在历史报告，不被本轮清单覆盖。组件准备没有应用自建条款弹窗或同意收据。

1. 确认 `tydct666/ArcCut_TydCT` 允许用户免登录下载 Releases；若源码私有，先调整为独立公开发布仓库并更新客户端固定配置。
2. 人工审核待上传源码，配置主分支和版本标签保护，再按用户授权上传。本地准备不执行此步骤。
3. 建立受保护环境 `production-release`，限制 main，要求维护者审批；加入签名密钥 secret，按“更新维护”保存离线备份。不要把 secret 写进 YAML。
4. 核验源码附带的第三方材料和可重建清单；完成发布审核后设置 `THIRD_PARTY_AUDIT_APPROVED=true`。此变量不跳过哈希、内容和签名检查。
5. 手动运行发布工作流并指定已经创建的版本标签。工作流构建、测试、签名、校验后仅创建草稿；资产先上传并回读核验，最后上传索引，不覆盖已有版本资产。
6. 审核草稿，以两个真实版本在公开 HTTPS 端点完成升级、项目恢复和故障验收，取得用户发布授权后再发布。当前没有运行远端 CI，也没有发布更新。

Actions 使用固定官方提交。PR 检查只读无签名凭据；签名仅在受保护的手动发布作业中执行。签名程序先确认私钥对应内置公钥，签名后立即反验。密钥输入为 PKCS8 DER 文件，公钥 Ed25519 原始 32 字节；具体命令参数见 `scripts/sign-update.cjs`。

## 验收边界

轻量包的根目录 README 来自 `release/portable-README.md`，`docs` 仅包含用户指南与用户版更新恢复说明。构建、签名协议和密钥维护说明留在源码文档中。`licenses`、`sources` 保留对应分发材料，源码归档内可包含开发文档。源码目录用于提交到 Git 仓库；轻量 ZIP 和更新元数据作为 GitHub Releases 资产，不提交进源码树。本地打包和准备上传目录均不会发布远端资产。

本机 Rust 故障注入覆盖每个备份/替换节点；此类测试不等于物理断电测试。localhost TLS 测试与真实 GitHub 发布端点测试分开记录。干净 Windows 10/11、真实 4/8 GB 机器、跨磁盘升级和公开端点未实测时必须标为待验。旧版本的媒体验收不自动覆盖新增更新器。

# 在线更新与恢复

0.17.0 是首个带更新器的便携版本。0.16.2 用户先手动下载并解压一次完整包。更新入口位于“软件设置 → 关于 ArkCut”，布局仍为两个设置分区。

程序启动完成且空闲后最多每 24 小时检查一次；手动检查立即执行。检查失败不影响本地剪辑。自动检查只影响设置入口和检查按钮的小红点，不主动显示弹窗、横幅或错误提示；手动检查发现新版本才打开弹窗，检查进度、无新版或失败结果只显示在设置页。首版下载完整 ZIP，界面显示真实体积，可取消；完整且已验证的下载可复用。导入、生成预览、导出、检查和返工期间不可安装。用户在手动检查弹窗中同意更新后才下载，完成后保存项目并重启；保存失败时停留在原程序。关闭弹窗清除本次同意，下载中关闭会取消下载；重新启动也不继承本次同意。

## 信任协议

固定仓库：`tydct666/ArcCut_TydCT`，稳定通道索引为该仓库 Releases 的 `latest/download/arkcut-update.json`。公开下载要求仓库或发布仓库允许免登录访问。本地准备不等于已上线；没有发布资产时显示暂不可用。

清单外层包含 `keyId`、Base64 `payload` 和 Ed25519 `signature`。签名覆盖原始 payload 字节，包含版本、平台、最小更新器版本、数据版本、源提交、资产 HTTPS 地址、长度、SHA-256、展开上限、组件版本和逐文件长度及哈希。Rust 使用 ed25519-dalek 的严格验证；Node 使用系统加密库签名。验证公钥在 `release/update-config.json`，私钥不进入构建、源码或便携包。此签名不是 Windows 可执行文件代码签名，不承诺消除 SmartScreen 提示。

下载仅接受 HTTPS 和指定仓库资产前缀，重定向限于配置中的 GitHub 资产域名。请求不携带录屏、项目、账户凭据或路径；仅 User-Agent 携带版本及平台。不读取系统代理凭据。每次读取有超时，取消可中断网络等待。更新清单最大 4 MiB，ZIP 小于 2 GiB，展开最多 4 GiB，按流写盘，不整包载入内存。

程序目录必须可写且不经过重解析点。ZIP 不得包含绝对路径、父目录、Windows 设备名称、ADS、链接、特殊文件、加密条目、重复路径或清单外文件。解包后再次检查全部长度、哈希以及包内 manifest 与签名清单的一致性。

## 更新事务

助手先复制到本目录的 `.arkcut-update`，核验自身哈希并确认已接管，再等待主程序真正退出。多开程序占用同目录时拒绝替换。更新开始前检查空间（展开、旧文件备份、安全余量），校验现有程序清单以及实际文件。

只替换 `ArkCut.exe`、`ArkCutUpdater.exe`、manifest、README、LICENSE，以及 licenses、sources、docs 内清单拥有的文件（旧包的 media/WebView2 文件仅为旧版本恢复保留）。项目存档、原片、成片、自定义配置不在替换范围，遇到非程序文件占据新路径时拒绝覆盖。未知目录不做清理。

新包解包并验证后，先运行其仅准备组件入口，检查签名清单中的组件要求与新程序一致。所需组件存储在 `%LOCALAPPDATA%/ArkCut/components`，按版本和哈希隔离；准备失败不开始替换，旧组件不会删除。健康检查只验证已有组件，不联网、不弹准备界面。Evergreen 由微软管理，应用回退复用满足最低版本要求的运行时。

每个同卷重命名前先落盘完整事务记录；备份和替换完成后刷新进度。新程序在独立数据及 WebView2 目录中初始化，并由前端确认就绪。健康检查失败或超时会回滚旧文件。成功后清理下载包与展开副本，保留一个旧版本备份；下一次更新确认当前程序完整后才清理该备份。被占用而延后的清理记录在 `cleanup.json`。生产构建不包含故障注入配置。

本版数据 schema 固定为 1，没有项目格式迁移；健康检查不打开或改写实际用户项目。未来不同 schema 的包会被拒绝，必须先实现带兼容副本的迁移和回滚。

## 中断恢复

1. 关闭同目录的所有 ArkCut，解除杀毒隔离或文件占用，确保磁盘有空间。
2. 若程序可启动，它会检测未完成事务并交给原助手恢复。若主 EXE 恰在替换时缺失，双击 `.arkcut-update/恢复更新.cmd`。
3. 助手根据 `transaction.json` 和文件哈希逐项恢复；完整性不明时保留现场，不删除未知文件。`last-result.json` 记录结果。
4. 若系统阻止助手运行，保留整个旧目录，把轻量便携包解压到新目录，再打开旧“项目存档”里的工程。不要把包覆盖到用户媒体目录。

失败回滚仅限当前事务已验证的备份；正常在线更新拒绝倒退版本。取消只作用于下载；开始文件替换后通过事务恢复保证一致性。

## 密钥保管与发布事故

维护者生成一次 Ed25519 私钥，离线备份到自己控制的加密介质，并测试能读取备份；不要发到聊天、邮件、仓库或源码压缩包。只在受保护的 `production-release` 环境配置 `ARKCUT_SIGNING_KEY_BASE64`，环境应限制主分支、要求维护者审批，外部分支检查没有签名权限。脚本从临时文件读取密钥且不打印，结束即删除临时文件。保留本地原始备份。

轮换：用旧密钥发布同时信任旧/新公钥的桥接版本；确认用户升级后再用新密钥签名，后续版本移除旧公钥。丢失旧密钥且没有桥接版本时只能人工离线升级信任根。发现私钥泄漏时应暂停发布，撤下更新索引并发布事故说明，要求用户离线获取新的可信版本。

撤回坏版本：暂停最新版索引入口，保留已发布资产不变；发布更高版本的修复包，不能把旧版本冒充新版本或原地覆盖既有 ZIP。事务失败的用户保留旧程序，已成功升级用户通过更高版本修复。生产端点完成真实 A/B 验收后才能签收在线更新能力。

参考：[Tauri updater](https://v2.tauri.app/plugin/updater/)、[Ed25519 严格验证](https://docs.rs/ed25519-dalek/3.0.0/ed25519_dalek/struct.VerifyingKey.html#method.verify_strict)、[GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。便携助手不使用 Tauri 的 Windows 安装器资产替代目录更新。
